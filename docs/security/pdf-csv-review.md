# PDF and CSV hardening (#70)

The PDF renderer uses pdf-lib with embedded standard fonts and plain text drawing only. User strings never become HTML, JavaScript, image/font URLs, filesystem paths or PDF actions. The hostile-content regression includes metadata/private/loopback URLs and file URLs, asserts no fetch, and checks that output contains no URI/action/script/embedded-file objects. Existing frozen snapshot golden hashes still pass.

PDF generation now has explicit per-process limits: two active renders, no waiting queue, 200 rows (the application's maximum), 250000 total string characters, 20000 characters per cell, 256 pages and 8 MB output. A five-second cooperative clock budget is checked during layout and long-word splitting. Long words use binary search rather than measuring every shrinking prefix. The limits constrain renderer allocations; this is not a separate operating-system heap limit or preemptive worker timeout. The final PDF serialization uses only the bounded document already constructed. No untrusted execution engine is present.

Limits can only be lowered by internal callers. Capacity is released on success and failure. The PDF link handler returns a generic private/no-store 503 with Retry-After when a rendering budget is exceeded; no document content, storage paths or secrets appear in the response. Existing signing throttles and role/company/object checks run first.

CSV exports use the existing typed RFC4180 writer: money is ASCII bigint cents, not display text. Text cells neutralise leading formula characters, fullwidth variants, leading whitespace and controls. Dates/integer columns validate their types. Authenticated exports require export.run, apply user/IP throttles before report generation, run inside a repeatable-read audited snapshot, refuse incomplete GST, and return private/no-store and nosniff. These controls are exercised by the report/export integration and CSV unit suites.

Validation includes hostile text, no fetch/PDF actions, maximum supported 200 ordinary invoice lines, oversized input, page/output limits, a deterministic clock exhaustion in word wrapping, concurrent capacity refusal and recovery after failure. Existing invoice PDF integration covers access, storage, immutable snapshots and private downloads. A separate independent review is still required before merge; final production audit remains #61.
